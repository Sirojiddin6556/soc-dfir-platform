# Руководство оператора SOC / DFIR эксперта (Operations Guide)

## 1. Введение

Данное руководство определяет порядок работы аналитика Центра мониторинга (SOC Tier 2/3) и эксперта по расследованию инцидентов (DFIR) с платформой **SOC/DFIR Platform & Live Cyber Range Workstation**.

Платформа работает в режиме **Evidence-Driven**: все сведения в интерфейсе формируются на основе фактических данных, снятых с целевого хоста или инфраструктуры, с подтверждением целостности через контентное хранилище (CAS).

---

## 2. Подготовка и запуск рабочей станции

### 2.1 Требования к привилегиям
Для полноценного сбора криминалистической информации о хосте Windows требуются права **Локального Администратора** (Local Administrator):
- Доступ к памяти и метаданным привилегированных процессов (`lsass.exe`, системные службы).
- Чтение параметров ветвей системного реестра `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run`.
- Опрос низкоуровневой таблицы сетевых сокетов через `GetExtendedTcpTable`.
- Доступ к перечислению прав запланированных задач через `ITaskService`.

> **Примечание**: Если приложение запущено без повышенных привилегий, модули сбора ограничатся объектами текущей пользовательской сессии.

### 2.2 Запуск
1. Запустите бинарный файл приложения от имени администратора:
   ```powershell
   # Запуск скомпилированного релиза
   .\target\release\desktop-app.exe
   ```
2. Приложение автоматически инициализирует локальный IPC-сервер (`http://127.0.0.1:8080`), смонтирует базу SQLite и CAS-хранилище и откроет главное окно **Forensic Cockpit**.
3. В нижнем статус-баре статус ядра должен отображаться как: `ЯДРО: АКТИВНО | IPC: СВЯЗАН | CAS: ГОТОВ`.

## 3. Регламент проведения расследования (Live Investigation Workflow)

```text
[1. Чистый Baseline] ──► [2. Глубокая инспекция хоста] ──► [3. Корреляция находок]
                                                                    │
[6. Экспорт отчёта]   ◄── [5. Анализ Timeline & MITRE]   ◄── [4. Сетевой Discovery & CVE]
```

### Шаг 1: Фиксация чистого состояния (Clean Baseline)
При первоначальном входе в систему рабочее пространство свободно от учебных или синтетических макетов:
- В верхнем блоке метрик: `Находки: 0`, `Критичные: 0`, `MITRE ATT&CK: 0`, `CVE: 0`.
- Пирамида боли находится в базовом состоянии: `0 угроз`.
- Вся поступающая телеметрия будет отражать исключительно реальную обстановку на исследуемой машине.

### Шаг 2: Глубокая инспекция хоста (Host Deep Inspection)
1. В верхнем блоке управления нажмите кнопку **«Глубокая инспекция хоста»**.
2. Модуль `platform-windows` выполнит комплексный сбор телеметрии:
   - Полное дерево запущенных процессов с фиксацией `PID`, `PPID`, командной строки и SHA-256 хэша исполняемого файла.
   - Таблица активных TCP-сокетов с сопоставлением PID процесса и удаленного IP/порта.
   - Записи автозагрузки в системном реестре и запланированные задачи Task Scheduler.
   - Службы Windows с проверкой незакавыченных путей (`Unquoted Service Path`).
3. В окне интерфейса появится карточка хоста (например, `PC-3002 | 127.0.0.1`) со статусом `ОБНАРУЖЕН` и сводкой собранных объектов.

### Шаг 3: Автоматическая корреляция и оценка рисков
Сразу после сбора телеметрии фоновый движок `correlation-engine` выполняет потоковую оценку правил (`CORR-WIN-001` .. `CORR-WIN-004`):
- Если обнаружен запуск `powershell.exe` из `WINWORD.EXE`, срабатывает правило `CORR-WIN-001e` (критичность `CRITICAL`, тактика `Execution`).
- Если зафиксировано подключение на порт `4444`, срабатывает правило `CORR-WIN-003a` (`Command and Control`).
- Если найдена служба с пробелами в пути, срабатывает `CORR-WIN-004` (`Privilege Escalation`).
- **Счетчики метрик** в шапке автоматически обновляются.
- **Пирамида боли (Pyramid of Pain)** наполняется верифицированными уровнями угроз.

### Шаг 4: Детальный анализ улик (Drill-Down Inspector)
1. В таблице **«Журнал находок и событий безопасности»** выберите строку с интересующей находкой и нажмите кнопку **«Осмотреть»**.
2. В правой боковой панели откроется **Инспектор улик**:
   - **Статус верификации**: `Кандидат (Candidate)`, `Подтверждено (Corroborated)` или `Доказано (Confirmed)`.
   - **Метрики риска**: Числовая оценка риска (0–100%) и сила доказательной базы (Evidence Strength).
   - **Таксономия MITRE**: Тактика, ID техники и гиперссылка на официальную матрицу ATT&CK.
   - **Уровень Пирамиды боли**: Хэши, IP-адреса, Домены, Артефакты, Инструменты или TTP.
   - **Сырой JSON объект наблюдения**: Полная криминалистическая выгрузка данных из CAS/SQLite.
3. Для фильтрации находок кликайте по соответствующим полосам **Пирамиды боли** (например, клик по уровню *TTPs* отфильтрует только сложные техники закрепления и аномалии процессов).

### Шаг 5: Сетевое обнаружение (Network Discovery)
1. Нажмите кнопку **«Сетевой Discovery»**.
2. Движок выполнит:
   - Опрос системного кэша ARP (`arp -a`) для выявления соседних хостов в широковещательном домене.
   - Чтение системной таблицы маршрутизации (`route print`) для определения шлюзов и внешних подсетей.
   - Экспресс-сканирование открытых портов ключевых сервисов (SMB 445, RDP 3389, HTTP 80/8080, SSH 22).
3. Список обнаруженных узлов сети отобразится в центральной панели с указанием IP, MAC, сетевых ролей и признака риска.

### Шаг 6: Инвентаризация ПО и сопоставление с CVE
1. Нажмите кнопку **«Инвентаризация ПО и CVE»**.
2. Модуль нормализации просканирует установленные пакеты Windows (реестр `Uninstall`, WMI) и преобразует их в спецификации **CPE 2.3** (например, `cpe:2.3:a:microsoft:edge:120.0.0.0:*:*:*:*:*:*:*`).
3. Движок уязвимостей выполнит сопоставление с локальной базой CVE:
   - Отобразит CVSS v3 score (Base Score).
   - Рассчитает вероятность эксплуатации в реальных атаках (**EPSS score**).
   - Установит флаг **CISA KEV (Known Exploited Vulnerability)** для уязвимостей, активно эксплуатируемых кибергруппировками.

### Шаг 7: Таймлайн атаки и экспорт отчета
1. В нижней панели изучите упорядоченный **Таймлайн расследования** по 4 дорожкам:
   - **Процессы**: Цепочки запуска и аргументы командной строки.
   - **Сеть**: Исходящие подключения, сокеты, сессии.
   - **Закрепление**: Модификации реестра и регистрация задач.
   - **События безопасности**: Сработавшие правила корреляции.
2. В блоке матрицы **MITRE ATT&CK** проанализируйте подсвеченные техники злоумышленника.
3. Нажмите кнопку **«Экспорт DFIR отчета»**:
   - Система сформирует юридически значимый криминалистический отчет.
   - Отчет включает сводку Chain of Custody, хэши CAS всех задействованных артефактов, список подтвержденных фактов и рекомендации по локализации инцидента.
