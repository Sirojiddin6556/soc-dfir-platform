# Архитектура SOC/DFIR Platform & Live Cyber Range Workstation

## 1. Введение и базовые принципы

Платформа представляет собой автономную рабочую станцию расследования инцидентов информационной безопасности и проведения практических киберучений (Blue Team Cyber Range). Архитектура спроектирована с соблюдением строгих принципов надежности, воспроизводимости и криминалистической чистоты:

1. **Local-First & Data Sovereignty**:
   Все собранные сырые артефакты, логи, дампы памяти, снимки сетевой активности и аналитические базы хранятся исключительно локально на рабочей станции исследователя. Никакие конфиденциальные данные не передаются во внешние облачные сервисы.
2. **Pure Safe Rust (`#![forbid(unsafe_code)]`)**:
   Все модули предметной области, парсеры и движки анализа строго запрещают использование `unsafe`-кода на уровне компилятора, исключая уязвимости переполнения буфера, use-after-free и состояния гонки памяти.
3. **Эпистемическая модель доказательств (Epistemic Segregation)**:
   Любое утверждение в системе строго классифицировано по типам (`AssertionType`):
   - `Fact`: Непосредственно наблюдаемое состояние, подтвержденное одним или несколькими источниками телеметрии.
   - `Inference`: Логический вывод или результат работы корреляционных правил.
   - `Hypothesis`: Предположение оператора или гипотеза атаки, требующая проверки.
   Каждая сущность имеет статус верификации (`VerificationState`): `Candidate` → `Corroborated` (2+ независимых источника) → `Confirmed` (3+ источников) либо `Disproved`.
4. **Криптографическая неизменяемость (Dual-Hash CAS)**:
   Сырые артефакты помещаются в контентно-адресуемое хранилище (CAS) с первичной адресацией по хэшу **BLAKE3** и контрольным расчетом **SHA-256** для подтверждения юридической целостности (Chain of Custody).

## 2. Модульная структура (Crates Workspace)

Платформа разделена на слабосвязанные модули с четким разделением ответственности:

```text
                               +-----------------------------+
                               |   Desktop UI (HTML5/JS)     |
                               +--------------+--------------+
                                              | IPC (JSON-RPC 2.0)
                               +--------------v--------------+
                               |   desktop-app (WebView2)    |
                               |   engine-server (RPC Host)  |
                               +--------------+--------------+
                                              |
        +-------------------------------------+-------------------------------------+
        |                                     |                                     |
+-------v-------+                     +-------v-------+                     +-------v-------+
| platform-win  |                     | correlation-  |                     | normalization-|
| platform-linux|                     |    engine     |                     |    engine     |
| priv-broker   |                     +-------+-------+                     | (EVTX, PCAP,  |
+-------+-------+                             |                             |  CPE / CVE)   |
        |                             +-------v-------+                     +-------+-------+
        |                             |  core-domain  |                             |
        |                             | (Epistemic)   |                             |
        +---------------------------->+-------+-------+<----------------------------+
                                              |
                               +--------------v--------------+
                               |        storage-cas          |
                               |       storage-sqlite        |
                               +-----------------------------+
```

### Назначение ключевых крейтов

| Крейт | Роль и ответственность |
| :--- | :--- |
| `core-domain` | Фундаментальные доменные типы: `Case`, `Observation`, `Fact`, `Evidence`, `Confidence`, `PainLevel`, `EntityType`. |
| `platform-windows` | Низкоуровневый сбор телеметрии Windows: процессы, родители, SHA-256, TCP сокеты, службы, точки закрепления (Run/Tasks). |
| `platform-linux` | Сбор телеметрии систем Linux через `/proc`, `/sys`, `netlink` сокеты и системные вызовы. |
| `privilege-broker` | Изолированный брокер с проверкой привилегий, валидацией параметров и аудиторским журналом вызовов. |
| `normalization-engine`| Парсинг EVTX, PCAP, сопоставление сетевых событий, генерация спецификаций **CPE 2.3** / **PURL** и матчинг **CVE**. |
| `correlation-engine` | Детерминированный движок сопоставления фактов по правилам `CORR-WIN-001` .. `CORR-WIN-004`, расчет доверия и рисков. |
| `timeline-engine` | Формирование упорядоченных дорожек событий (Process, Network, Persistence, Security) для расследования. |
| `graph-engine` | Построение ориентированного ациклического графа зависимостей сущностей и цепочек атак. |
| `storage-cas` | Хранилище блобов с дедупликацией на базе хэшей BLAKE3 и метаданными размера/типа контента. |
| `storage-sqlite` | Реляционная база на 19 нормализованных таблицах с поддержкой режима WAL и сохранением истории доказательств. |
| `ipc-protocol` | Спецификация сетевых кадров, кодек фреймов (длина + payload), типизированные DTO и ошибки RFC 7807. |
| `engine-server` | Центральный сервис диспетчеризации запросов, управление жизненным циклом сессий и фоновыми задачами. |
| `desktop-app` | Нативная десктопная оболочка Windows (WebView2) со встроенным веб-сервером и локальным IPC-каналом. |

## 3. Криминалистическое хранилище данных

### 3.1 Content-Addressed Storage (CAS)
Каждый загружаемый или извлекаемый артефакт (файл, дамп, лог) помещается в CAS-каталог `.storage/cas/objects/`:
- Имя файла: первых 2 байта hex-хэша BLAKE3 образуют подкаталог, оставшиеся 60 символов — имя файла.
- Неизменяемость: файлы создаются с правами только для чтения.
- Дедупликация: повторный сбор идентичного артефакта не дублирует дисковое пространство.

### 3.2 Реляционная схема SQLite (19 таблиц)
База данных работает в режиме `PRAGMA journal_mode=WAL` и `PRAGMA foreign_keys=ON`:
- `cases` — метаданные расследований и дел.
- `artifacts` — реестр улик с привязкой к CAS-хэшам.
- `evidence_objects` — нормализованные криминалистические объекты.
- `observations` — атомарные сырые наблюдения, зафиксированные инструментами.
- `facts` — верифицированные факты с уровнем уверенности, риском и уровнем Пирамиды Боли.
- `hypotheses` — рабочие гипотезы эксперта.
- `mitre_mappings` — проекции на матрицу MITRE ATT&CK (Тактика, Техника, Sub-technique).
- `timeline_events` — синхронизированные события для временной шкалы.
- `audit_events` — неизменяемый журнал действий системы и оператора.

## 4. Протокол IPC и методы взаимодействия

Связь между фронтендом (UI) и бэкендом (Rust Engine) осуществляется по протоколу JSON-RPC 2.0 поверх локального HTTP/WebSocket транспорта `http://127.0.0.1:8080/rpc`.

### 4.1 Формат запроса
```json
{
  "api_version": 1,
  "request_id": "req-0191f630-3c22-7d22-9011-8729583bc123",
  "case_id": "0191f630-3c22-7d22-9011-8729583bc124",
  "method": "host.deep_snapshot",
  "params": {
    "target": "localhost"
  }
}
```

### 4.2 Ключевые методы API

| Метод | Назначение |
| :--- | :--- |
| `host.deep_snapshot` | Сбор полного слепка Windows: процессы, хэши, сокеты, службы, автозагрузка. |
| `host.correlate` | Потоковая корреляция наблюдений хоста, генерация фактов и расчет Пирамиды Боли. |
| `net.discover` | Обнаружение сети: парсинг ARP-кэша, таблицы маршрутов, сканирование портов. |
| `scan.cve` | Инвентаризация ПО, генерация CPE 2.3 и PURL, сопоставление с локальной базой CVE. |
| `case.create` / `case.list` | Управление делами и сессиями расследования. |
| `evidence.ingest` | Импорт криминалистических артефактов в CAS-хранилище. |
| `report.generate` | Формирование итогового отчета в форматах JSON, Markdown или PDF. |

### 4.3 Обработка ошибок (RFC 7807 Problem Details)
В случае сбоя или нарушения валидации бэкенд возвращает стандартизированный ответ:
```json
{
  "type": "https://soc-dfir.local/errors/validation-error",
  "title": "Некорректные параметры запроса",
  "status": 400,
  "detail": "Поле 'target' содержит недопустимый IP-адрес или hostname",
  "invalid_params": ["target"]
}
```

```text

          ▼ 1. Извлечение (WinAPI / Raw Sockets / ARP Cache)
   [Raw Snapshot]
          │
          ▼ 2. CAS Storage & Нормализация
   [Observation Stream]
          │
          ▼ 3. Детерминированная корреляция (CORR-WIN-001..004)
   [Verified Facts] ──► [SQLite WAL Storage]
          │
          ├──────────────────────────┬──────────────────────────┐
          ▼                          ▼                          ▼
 [Timeline Lanes]          [MITRE ATT&CK Matrix]      [Pyramid of Pain]
          │                          │                          │
          └──────────────────────────┼──────────────────────────┘
                                     ▼
                       [Interactive Forensic UI]
                                     │
                                     ▼ 4. Аудит и экспорт
                           [Final DFIR Report]
```
